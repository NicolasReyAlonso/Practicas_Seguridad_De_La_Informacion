\chapter{Ordenador y sistema operativo}

El equipo analizado es el ordenador que utilizo de manera habitual tanto para tareas académicas como profesionales: un \textbf{Apple MacBook Air} con chip Apple Silicon, sobre el que corre la versión 26.3.1 de macOS (ya actualizaré cuando termine el TFG). A lo largo del capítulo se describen, en formato profesional, todos los aspectos que el enunciado solicita ``rellenar entre líneas''.

\subsection{Fecha límite de actualizaciones de mantenimiento y de seguridad}
\label{subsec:eol}

Apple no publica un calendario formal de fin de soporte para cada versión de macOS, pero sí mantiene un criterio bien documentado: la versión \textit{actual} recibe todas las actualizaciones (funcionales y de seguridad), la inmediatamente anterior recibe \textit{únicamente parches de seguridad} y la \textit{N-2} recibe parches de seguridad ``en la mayoría de los casos'' hasta el lanzamiento de la siguiente versión mayor. En la práctica esto se traduce en una ventana de soporte efectiva de \textbf{aproximadamente tres años desde el lanzamiento} de cada \textit{major release}. macOS Tahoe (versión 26) se lanzó en el ciclo 2025, por lo que el equipo recibe la totalidad de las actualizaciones de seguridad y mantenimiento al menos hasta el otoño de 2028 según la cadencia histórica de Apple.

\section{Políticas de seguridad y mantenimiento}
\label{sec:politicas_seguridad}

\subsection{Gestión de cuentas de usuario}
\label{subsec:usuarios}

El equipo tiene configurada una \textbf{única cuenta} de usuario, con privilegios de administrador:

\begin{itemize}[leftmargin=*]
    \item Número total de cuentas: 1 (Aparte de root).
    \item Cuentas con privilegios de Administrador: 2 (\texttt{NicolasReyAlonso} y \texttt{root}).
    \item No existen cuentas estándar adicionales para el uso cotidiano.
\end{itemize}

Esta configuración --- una única cuenta administradora utilizada para todo --- es la que el manual señala explícitamente como una de las \emph{negligencias} más comunes en los entornos domésticos. Volveremos sobre este punto en las conclusiones.

\subsection{Política de contraseñas}
\label{subsec:contraseñas}

\begin{itemize}[leftmargin=*]
    \item \textbf{Requisitos mínimos:} macOS no impone unos requisitos mínimos estrictos; muestra un indicador visual de calidad mientras se escribe. En mi caso, la contraseña local tiene \textbf{14 caracteres como mínimo}, combinando mayúsculas, minúsculas, números y símbolos.
    \item \textbf{Frecuencia de cambio:} no hay frecuencia obligatoria. Sigo el criterio de \textbf{cambio voluntario cada $\approx$6 meses}; Apple desaconseja explícitamente el cambio forzado y frecuente porque empíricamente conduce a contraseñas más débiles, lo que es consistente con la recomendación más reciente del NIST SP 800-63B.
    \item \textbf{Autenticación multifactor (MFA):} activada. Apple ID exige doble factor con dispositivo de confianza y, además, dispongo de \textbf{códigos TOTP en la app nativa Contraseñas} (sucesora de \textit{Authenticator}) para los servicios que lo soportan.
    \item \textbf{Autenticación biométrica:} Touch ID activado tanto para el desbloqueo del equipo como para la confirmación de operaciones \texttt{sudo}, compras y aprobaciones de cambios de seguridad del sistema. El factor biométrico se almacena cifrado dentro del \textit{Secure Enclave}.
    \item \textbf{Bloqueo automático y otras restricciones:} pantalla con bloqueo automático tras 5 minutos de inactividad y exigencia de contraseña al despertar.
\end{itemize}

\subsection{Política de copias de seguridad (\textit{backup})}
\label{subsec:copias_seguridad}

\begin{itemize}[leftmargin=*]
    \item \textbf{Herramienta:} Time Machine, copias \textbf{completas} (con \textit{snapshots} incrementales gestionados por APFS internamente).
    \item \textbf{Frecuencia:} cada $\approx$3 meses o de forma puntual antes de cambios significativos en el sistema o tras finalizar proyectos que no estén respaldados por Git/GitHub.
    \item \textbf{Almacenamiento:} disco duro externo USB-C dedicado a Time Machine. El disco \textbf{permanece desconectado entre copias} y se monta sólo para realizarlas, lo que cumple el requisito de copia \textit{offline} que el manual considera imprescindible frente a ataques de \textit{ransomware}.
    \item \textbf{Almacenamiento en nube:} no hay copias automáticas hacia iCloud Drive de la totalidad del sistema; considero que aumenta mi seguridad el tener mis datos en la menor cantidad de sitios en la nube posible.
    \item \textbf{Procedimiento de recuperación:} en caso de fallo, el sistema puede restaurarse arrancando en \textit{Recovery Mode} (Cmd+R durante el encendido) y seleccionando ``Restore from Time Machine Backup'', siguiendo el asistente para elegir el \textit{snapshot} adecuado.
\end{itemize}

\section{Política y gestión de actualizaciones (\textit{Patch Management})}
\label{sec:actualizaciones}

\subsection{Requisitos y proceso de actualización}
\label{subsec:actualizacion_proceso}

\textbf{Fuente y revisión de las fechas límite de mantenimiento:}
\begin{itemize}[leftmargin=*]
    \item \textbf{Fuente principal:} el módulo \textit{Software Update} de macOS (\texttt{System Settings $\to$ General $\to$ Software Update}), complementado con los avisos de Apple Security Releases.
    \item \textbf{Frecuencia de revisión:} cada $\approx$3 meses junto con la copia de seguridad, o de forma inmediata cuando Apple emite un aviso de actualización crítica.
\end{itemize}

\textbf{Descripción detallada de la política de actualizaciones:}
\begin{itemize}[leftmargin=*]
    \item \textbf{Tipo de actualizaciones permitidas:} se permiten descargas automáticas en segundo plano, pero la \textbf{instalación se autoriza siempre manualmente}; es decir, no hay instalación automática habilitada.
    \item \textbf{Aplicaciones gestionadas por \texttt{brew}:} se actualizan mediante \texttt{brew update \&\& brew upgrade}, también de forma manual.
    \item \textbf{Aplicaciones de App Store:} con descarga automática activada e instalación manual.
    \item \textbf{Frecuencia de instalación:} tras realizar la copia de seguridad correspondiente, para mantener la posibilidad de \textit{rollback}.
    \item \textbf{Procedimiento de prueba:} las actualizaciones se aplican directamente sobre el sistema productivo. No se utiliza un entorno de pruebas previo.
\end{itemize}

Esta política de \emph{descargar automáticamente, instalar manualmente con frecuencia trimestral} es deliberadamente conservadora --- prima la previsibilidad sobre la \textit{ventana de exposición} ---, pero el manual de la asignatura es taxativo a este respecto: cuanto mayor sea esa ventana, mayor es la probabilidad de que un \textit{exploit} público de un fallo ya parcheado nos alcance. En las conclusiones se discute esta tensión y se propone una mejora.
